# 전체 코드베이스 감사·정리 (2026-08-24)

## 배경

사용자가 두 프로젝트를 요청: (1) 적중률 자기학습/개선 기능, (2) 프론트엔드·백엔드·LLM 호출 전체 감사 후 버그·스파게티·죽은 코드 정리 + 전/후 비교 리포트. 서로 얽혀 위험하므로 분리했고, (2)를 먼저 진행하기로 함.

`문제점 및 보완점/트래커.md`(옵시디언 vault)에 `runDailyAnalysis`(740줄)·`runDailyPipeline`(350줄) God Function 분해가 "회귀 위험이 커서 사용자가 스코프에서 제외"한 이력이 있음. 이번에도 이 두 함수(핵심 채점 파이프라인)는 코드 변경 없이 분석·설명만 한다.

## 범위

**분석만(코드 변경 없음)**: `runDailyAnalysis`, `runDailyPipeline` — 무슨 일을 하는지, 왜 위험한지 비전공자 눈높이로 설명.

**감사·수정 대상**: 그 외 전체 — 프론트엔드 컴포넌트/페이지, API 라우트, DB 접근 코드, LLM 호출 코드(`bigtech-reasons.ts`의 방향성 모순 검증 부재 등 트래커에 이미 열려있는 이슈 포함), 스크립트, 죽은 코드.

**제외**: 채점 결과가 바뀔 수 있는 리팩터(엔진과 동일한 이유로 제외).

## 접근 방식

1. 자동 도구로 1차 스캔: `ts-prune`(미사용 export), `depcheck`(미사용 npm 패키지), `eslint --max-warnings=0`(미사용 변수/import). devDependency로 임시 추가 후 작업 끝나면 제거.
2. 도구가 찾은 후보를 코드 직접 읽어 재확인(동적 import·프레임워크 암묵 호출 등 오탐 제외) — 진짜 안 쓰는 것만 "죽은 코드"로 분류.
3. 안전하게 고칠 수 있는 버그·스파게티 코드부터 수정(중복 로직, 매직 넘버, 과도한 삼항연산자, 프롬프트 후처리 중복 등 — 지난 감사와 동일 기준).
4. 기존 vitest 테스트(현재 99개 통과), lint, `tsc --noEmit` 타입체크로 검증.
5. 로컬 git 커밋까지만(push 안 함, 배포 안 함) — 사용자가 리포트 확인 후 별도로 push 요청.

## 산출물

- 로컬 커밋된 코드 수정.
- Artifact(브라우저)로 발행하는 비전공자용 한글 리포트:
  - 핵심 엔진(`runDailyAnalysis`/`runDailyPipeline`) 설명 섹션.
  - 전/후 비교 표: 파일 위치 | 문제 종류(버그/스파게티/죽은 코드) | 고치기 전 | 고친 후 | 왜 문제였는지.
  - 요약 통계(발견/수정 건수, 삭제한 죽은 코드 줄 수).
  - "로컬 커밋까지만 됐고 실제 배포는 안 됐다"는 안내.
